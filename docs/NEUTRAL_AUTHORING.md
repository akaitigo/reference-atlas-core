# 中立的なAuthoring契約

Template、Generator、Docs、Skillは、検証対象、比較条件、再現手順、Evidence、既知の制約、未解決Gapを事実ベースで記述する。

- 作者、Organization、Repositoryを称賛する表現を生成しない。
- 「世界一」「唯一」「決定版」など検証不能な優越表現を品質根拠にしない。
- `subject-definitive`はGateが返すCompletion Class識別子としてだけ使用し、宣伝文句へ転用しない。
- GitHub namespace、URL、導入Command、License／Copyrightなど技術的・法的識別に必要な場合を除き、個人名やAccount名を品質説明へ使わない。
- 比較は同じVersion、Platform、入力、予算、測定方法を固定し、不利な結果や既知の制約を削除しない。
- 品質はTarget件数や形容ではなく、Authority Lock、Runtime Artifact、Trace、Skill Eval、Provenance、Non-regression Gateで示す。
